# Research — desktop auto-update from GitHub Releases

## In-repo prior art

- **CLI channel manifest** (`apps/aster/src/cli_pair_update.rs`):
  `OFFICIAL_RELEASES = https://github.com/aster-ai-lab/aster/releases` +
  `latest.json` generated by `release-aster-cli.yml` with per-platform
  sha256. The desktop manifest mirrors this shape under a namespaced
  asset (`desktop-latest.json`) so the two channels never alias.
- **Why a dedicated channel tag**: `/releases/latest` resolves to the
  newest release of the WHOLE repository. The CLI publishes releases too,
  so a `/releases/latest/download/desktop-latest.json` URL would 404
  whenever a CLI release is newest. The desktop channel therefore pins
  `releases/download/desktop-stable/...` and the publish job clobbers
  that release's assets.
- **Anonymous HTTPS through curl** (`apps/studio/src-tauri/src/providers.rs`
  `curl_get` / `curl_config_timeout`): curl driven from config stdin so
  nothing rides argv; the updater reuses the pattern without the API-key
  header (public asset). `--fail` maps the whole HTTP-error class to
  `not_published` (denied and missing share the not-found contract);
  timeouts/DNS stay `failed`.
- **Replace machinery** (`app_updater.rs` `install_zip` →
  `delivery_manifest::validate` → `verify_signature` → `replace_bundle`
  backup → `schedule_relaunch` with restore-on-failure): untouched; only
  the feed layer in front of it changes.
- **Preference**: `app.dist.auto_update.enabled` already exists in
  `data/classification.json` (default true) — no classification change.
- **Packaging** (`apps/studio/scripts/package-host.sh`): produces the
  sealed `Aster.zip` under `target/release/bundle/macos/` and codesigns
  ad-hoc; the workflow uploads that zip and nothing else.

## Decisions carried from the plan conversation (2026-10-22)

- D1 manifest shape: `{product, channel, version, published_at, notes,
  platforms: {darwin-aarch64: {url, sha256, size}}}` — accepted.
- D2 signatures: codesign identity pin now; Ed25519 manifest signature
  deferred to the first non-macOS channel — accepted (spec assumption).
- D3 cadence: mount + hourly re-arm, 24 h gate, manual install only —
  accepted.
- D4 notarization: deferred; needs the owner's Apple Developer ID —
  recorded as an open key, not blocking.
- D5 versioning: workflow_dispatch input; assets versioned
  `Aster-darwin-aarch64-vX.Y.Z.zip` on the shared channel release.
