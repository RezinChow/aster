# Native execution contract

## 原生执行边界

原生 profile 中，Rust 模型循环调用 Power 进程内执行、驻留和受支持的 CUDA 内核/通信库。HTTP 参考执行器没有参与 token 计算。内核可以有经过审阅的 CUDA/C ABI 实现；“原生”不要求所有数学实现都用 Rust。

构建与选择是两个不同条件：启用 native feature 不能证明某模型图已实现；注册后端不能证明实际 GPU dispatch 已发生。验收必须记录实际执行身份，并在参考 HTTP 服务不可用时完成小模型原生生成。

## 配置与能力

- 产品配置使用拥有者的 ACL；显式 CUDA 请求不可自动退回 CPU、代理、另一量化或模型。
- 新 profile/策略字段使用闭集；缺少能力、内存、模型绑定或成本观测时返回具体拒绝。
- 保持现有 F32 图 API；低精度与集体通信作为独立 typed capability，不偷改旧调用者精度。
- 模型 crate 依赖本地 Power；Power 通用 crate 不依赖具体模型 crate。服务在 composition owner 组合后端，避免循环依赖。

## 状态提交

每个请求持有现有 execution permit。batch 只组合各自拥有的状态行，不共享可变 KV。
计算完成并通过验证后才能原子提交状态。取消、超时、rank 失败和草稿拒绝必须回到可解释的最后提交边界；释放设备/内存预算后才能复用 slot。
草稿回滚覆盖 KV、压缩/SWA 状态及模型需要恢复的其他状态；不能仅回退输出 token 数。

## 缓存

引擎负责 token-exact 前缀语义。通用资源层管理 bytes、admission 与所有权，不解释“某层是共享 KV”等模型含义。
一个 EP8 组内部的八个 rank 共同服务一个模型执行，不能当成八个完整 KV 副本进行网关随机路由。
前缀预测与真实缓存命中分开计量；淘汰、重启和 epoch 更新必须使旧提示失效。

## 质量与性能

- 模型格式一致、目标权重一致才做执行器加速倍率；XQ 与官方检查点各有自己的数值/质量参考。
- 最小正确控制组关闭 speculation 与 replay 变更。每个候选一次只改已记录的机制，再通过组合验收。
- SWA bounded replay 是模型相关的计算变更，单独验证数值和任务质量，不宣称严格位级等价。
- DSpark 所有候选都由目标验证；confidence 用于选择预算，不可代替验证。
- 总吞吐、单请求速度、TTFT、ITL 和失败率共同保留；显存占用或 SSE chunk 数不是有效 token 计数。

## 晋升

先冻结预算，后运行候选。出现错误答案、状态污染、身份不符、内存超限或恢复失败，拒绝晋升。
性能未超过测量波动时保留控制组。某个 profile 的单请求或总吞吐达标，只更新对应目标字段。
