# Bundled skills and future update resources

The installed host previously resolved built-in skills and the legacy review link only through `CARGO_MANIFEST_DIR/../resources/skills`. A package moved away from its checkout therefore could not load those skills. Resource hashes alone also allowed an otherwise sealed package to omit them.

`bundled_skills.rs` now resolves macOS `Contents/Resources/skills`, Linux `/app/Resources/skills`, and the declared Windows sibling `skills` layout. The first two use the same executable-relative `../Resources` convention as the existing companion launcher. Release code never uses the checkout. Debug code uses it only when no delivered generation exists; on Windows, whose resource root is the existing executable directory, both `skills` and the inventory must be absent. A partial, malformed, or symlinked generation cannot trigger fallback. Existing user skill directories/links and review ownership rules are preserved.

The single shared contract is `apps/studio/resources/bundled-skill-files.txt`: 63 regular, nonempty files across eight skills, including relative references, scripts, ACL declarations, and license notices. Composer owns copying and sealing those resources. Native runtime code includes that contract and requires exact delivered inventory bytes and an exact tree. It refuses symlinks, unknown/extra directories or files, empty files, skills over the existing 256 KiB document limit, and total resources over 64 MiB.

The updater deliberately has a different contract from the running host. A future signed target may add or remove resources. It parses the target inventory once, with a 64 KiB/4096-entry bound; UTF-8, sorted, unique relative `/` paths; no empty, dot, parent, absolute, backslash, colon, or control-character components; and a root `SKILL.md` for each declared skill. It validates the exact regular/nonempty tree and returns those same paths to require every resource and inventory in the target generation hashes. It does not pin a future target to the current host's 63 paths. Product, signature, newer-version, and rollback checks remain at their existing seams.

The maintained before cases recorded real assertion failures: source-only resolver 3/3, omitted/extra/redeclared skill resources 3/3, a legitimately expanded future target 1/1, and the Windows debug layout 1/1. Intermediate direct test compilation logs for one parallel two-feature run shared a filename; that collision is disclosed in the receipt and replaced by distinct per-tenant logs, not counted as separate evidence.

Final real Studio test crates were compiled with each tenant feature using the isolated dependency snapshot. Each passed updater 35, resolver 4, existing built-in preservation 1, skill ownership 1, and bundled review replacement 1. The same final binaries passed Aster's four pure-local account-boundary cases and ToYou's one managed boundary case. These are overlapping filters and are not combined with earlier runs. Both feature compiles succeeded. Scoped rustfmt and diff checks passed.

The authoritative current source receipt is [native-source-ready-bundled-skills.json](native-source-ready-bundled-skills.json), 40 paths, SHA-256 `6bcea132bb14e93dcd3d589a1db9b2905ed569b37a1580a9a7f52bdb27da11d0`. [native-bundled-skills-final-validation.json](native-bundled-skills-final-validation.json) binds the final compiler receipts, executed binary hashes, per-tenant logs, before evidence, and an empty source-drift list.

These tests do not establish physical Windows compatibility or final installer contents. Mac/Linux/Windows resolver layouts are hermetic filesystem fixtures on macOS. Actual Cargo builds, copied resource inventory/signatures, installed package checks, and CUA remain separate gates owned by the parent and packaging agent. The ask-form 12-component table repair and Core tests establish the source contract; they alone did not prove that the skill shipped. No credentials, existing member profiles, or user skill contents were copied or migrated.
