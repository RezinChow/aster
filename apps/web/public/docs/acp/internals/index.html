ASTER ACP / 协议原理

ACP 把哪些事情交给 Core

按一次客户端请求拆开协议适配、可信宿主、Core 会话和界面事件。

Aster ACP 9.1.6 · 当前源码·2026-10-28

先把“客户端”与“执行者”分开

客户端接收用户输入并显示运行过程。 a3s-code-acp 接收 ACP 消息，再调用 Core。 Core 接纳执行、调用模型、治理工具并检查完成。 协议适配器把运行事件送回客户端。

例如，用户在终端提交日期导出修复。 终端发送文本，ACP 找到对应会话。 Core 执行任务，ACP 翻译事件。 终端用事件中的原始 ID 更新工具行。

三层结束含义怎样区分

层次结束表示什么还要核对什么
ACP prompt本轮协议请求返回Core 的运行与完成依据
Core Run原始执行进入终态资源结清与该轮证据
Durable Goal原目标满足完成条件全部步骤、等待与切片

end_turn 是协议停止原因。 它不能独自证明长期目标已经完成。 客户端需要结合对应的 Core 状态显示结果。

从连接到一轮执行

客户端先调用 initialize。 随后创建或恢复会话，再提交 session/prompt。 运行期间，客户端消费 session/update。 需要确认时，客户端回答原始权限请求。 本轮结束后，客户端读取 prompt 响应。

入口会拒绝哪些内容

当前 ACP prompt 接受文本内容块。 图片、音频、资源和资源链接会返回参数错误。 拒绝发生在模型调用之前。 Core 内部具备某项能力，不代表 ACP 已暴露该能力。

标准 ACP 方法与宿主扩展也要分开。 a3s/goal/* 和 a3s/review/* 属于宿主扩展。 未知扩展方法返回 method_not_found。 入口：宿主方法闭集 L45 ↗。

哪些信息必须来自可信宿主

信息作用工作区文本的边界
模型与服务配置选择实际模型调用路径保留配置层的信任规则
权限与沙箱判定工具调用提示词不能放宽
goal_control限制自动续跑工作区声明不能提高上限
工作策略选择选择已编入的策略客户端不能提交任意策略代码
完成证明选择安装宿主检查模型不能自行安装证明器

每项信息由其原入口准入。 ACP 不应把普通文本解释为额外执行权限。

    pub(super) fn prompt_text(prompt: &[acp::ContentBlock]) -> acp::Result<String> {

        let unsupported = |kind: &str| {

            acp::Error::invalid_params().data(format!(

                "unsupported prompt content block `{kind}`; this agent accepts text only and did not send the request to the model"

            ))

        };

        let mut text = Vec::new();

        for block in prompt {

            match block {

                acp::ContentBlock::Text(content) => text.push(content.text.as_str()),

                acp::ContentBlock::Image(_) => return Err(unsupported("image")),

                acp::ContentBlock::Audio(_) => return Err(unsupported("audio")),

                acp::ContentBlock::Resource(_) => return Err(unsupported("resource")),

                acp::ContentBlock::ResourceLink(_) => return Err(unsupported("resource_link")),

                _ => return Err(unsupported("unknown")),

            }

        }

        Ok(text.join("\n"))

    }
