重放恢复控制状态

恢复会话时，Core 从原始事实重建运行投影。 已经有完整结果的调用支持沿记录继续判断。 结果缺失的外部操作仍保留不确定性。 重放日志本身不会撤销或重新执行外部效果。

例如，外部服务已接受写入。 本地进程随后在保存结果前退出。 恢复后的日志缺少结果，外部写入却可能已经生效。 直接重试可能造成第二次写入。

四种材料分别承担什么职责

材料用途权威边界
事实日志重建控制与原始效果关联不被摘要中的声明覆盖
检查点保存已提交状态的缓存投影恢复时核对身份与来源
对话摘要帮助模型接续推理不能授予权限或接受步骤
当前工作区核对真实文件与当前对象不能仅凭历史缓存推断现状

缓存加快接续，事实提供依据。 两者矛盾时，恢复流程需要报告具体缺口。 宿主不应把缓存存在当成原始效果已证明。

ACP 恢复为什么检查工作区

会话 ID 必须指向对应工作区的原会话。 ACP 对启动工作区与请求目录做规范化核对。 随后查找原始会话来源。 缺少来源时返回资源不存在。 快照存在时，还会检查快照中的会话与工作区。

这样能避免把另一个项目的缓存接入当前任务。 实现：恢复准入 L37 ↗。

发现未决效果后怎样调查

警告：结果不明时，重试外部写入可能产生重复效果。

  1. 读取原运行的工具身份。
  2. 核对原始调用参数。
  3. 查找原效果回执。
  4. 检查真实目标对象的状态。
  5. 记录缺失或新增的观察依据。
  6. 按原接口核对结清状态。

若来源仍无法证明，运行保留未决状态。 模型的推测不会清除该状态。 宿主需要继续取得可核对的证据。

recovery.unproved 说明什么

recovery.unproved 记录无法证明的恢复来源。 记录携带内容绑定的身份与原因。 该记录本身不证明外部效果成功。 该记录也不授权重新执行效果。

这是一项负面来源记录。 它把“证据缺失”与“已经失败”区分开。 宿主应保留这一区别，避免显示虚假的成功状态。

长期目标的失联切片怎样处理

目标切片的执行者退出后，切片可能尚未结清。 下一次 tick 会要求先核对原运行。 reconcile_goal_slices 处理已经失去执行者的切片。 核对过程不会直接重放原始工具操作。 未结清的实际效果仍使用原有检查路径。

“进程消失”“切片结清”“效果已知”是三个事实。 宿主需要分别核对。
